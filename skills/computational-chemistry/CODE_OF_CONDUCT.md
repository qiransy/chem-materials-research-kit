# 参与者行为准则

## 共同承诺

我们承诺为所有参与者提供开放、尊重、专业且不受骚扰的协作环境，不因经验水平、教育背景、年龄、身体状况、民族、国籍、性别、性别认同、性取向、宗教、经济状况或其他个人特征而区别对待。

本项目同时涉及软件工程与科研方法。讨论可以严格，但必须针对代码、证据、方法和可复现性，不得针对个人进行贬低或攻击。

## 期望行为

参与者应当：

- 使用清晰、尊重和专业的语言
- 对不同经验水平的使用者保持耐心
- 针对问题提供可核查的依据、复现步骤和改进建议
- 承认错误并及时修正
- 尊重未发表数据、许可证、署名和知识产权
- 在科学结论存在不确定性时明确说明证据边界
- 将安全漏洞通过 `SECURITY.md` 指定渠道私密报告
- 关注修改对普通用户、无编程基础用户和不同操作系统的影响

## 不可接受的行为

以下行为不可接受：

- 侮辱、威胁、骚扰、歧视或针对个人的攻击
- 发布他人的私人信息、凭据、联系方式或未发表数据
- 故意提交虚假测试、虚假计算结果或伪造的科学依据
- 将商业软件结果错误描述为由其他软件产生
- 在没有证据的情况下宣称计算收敛、机制已证明或结果可直接发表
- 利用 Issue、Pull Request 或讨论传播安全漏洞利用细节
- 反复偏离主题、恶意干扰协作或无视维护者的合理管理要求

## 科学讨论规范

涉及软件参数、物理量、单位、参考态、模型边界和证据强度的争议，应优先提供官方文档、原始论文、可复现测试或最小示例。观点分歧本身不构成违规，但不得把未经验证的主张包装成确定事实。

## 执行责任

维护者负责解释和执行本准则，可对不当内容进行编辑、隐藏或删除，并根据严重程度采取警告、限制互动、临时封禁或永久禁止参与等措施。

对于善意但不完整的贡献，维护者应优先说明需要修改的内容；对于恶意行为、安全滥用、数据泄露或科研不端，可以直接采取更严格措施。

## 适用范围

本准则适用于仓库、Issue、Pull Request、代码审查、讨论区，以及代表本项目参与的其他公开或私密沟通场景。

## 联系方式

普通行为问题可联系仓库维护者。涉及隐私或安全风险的情况，请按照 `SECURITY.md` 通过私密渠道报告。
