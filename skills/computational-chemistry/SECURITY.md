# 安全策略

## 支持范围

安全修复以当前主分支和最新正式版本为主要支持对象。已经停止维护的旧版本可能不会获得回溯修复；如问题同时影响当前版本，请以当前版本为基准报告。

## 私密报告安全问题

以下问题不得在公开 Issue 中披露：

- 任意命令执行、远程命令执行或不受控子进程调用
- 未经确认覆盖、删除或移动用户文件
- 路径遍历、目录逃逸或对项目目录外文件的访问
- GitHub Token、SSH 密钥、账户凭据或许可证信息泄露
- 本地 Flask 页面中的 HTML、脚本或模板注入
- 不受限的 `pwsh` 调用、交互式 PowerShell、后台作业或缺少超时的执行
- 审批绕过、伪造 `review_decision.json` 或接受旧审批结果
- 错误 `request_id`、`stage` 或 `content_hash` 被接受
- 本地服务意外绑定到公网地址
- 日志、验证文件或示例中泄露未发表科研数据

请通过 GitHub 的私密安全报告功能联系维护者。若仓库未启用该功能，请发送邮件至 `jianzu.shen@outlook.com`，主题以 `[SECURITY] Computational Chemistry Skill` 开头。

报告应包含：受影响版本或提交、操作系统与 Python 版本、复现步骤、预期行为、实际行为、相关日志、影响范围，以及已知的临时缓解方法。请删除 Token、密码、私钥、许可证服务器地址、真实集群账户和未发表数据。

## 响应目标

维护者会尽量在 7 天内确认收到报告，在完成初步复现后说明影响范围和处理计划。复杂问题的修复时间取决于影响程度、兼容性和端到端回归测试结果。

在修复发布前，请勿公开利用细节、复现脚本或能够绕过审批的具体方法。

## 本地浏览器服务安全边界

默认简单流程使用静态 `.review/review.html`，页面不得执行任意命令，且 `.review/` 不得提交。自动打开浏览器失败时提供本地路径，不生成额外状态文件，也不降低输入校验。

以下要求适用于显式启用的高级 Flask 审查服务。

浏览器审查服务默认仅绑定 `127.0.0.1`。除非用户明确配置并理解风险，不应绑定 `0.0.0.0`、公网地址或可被局域网其他设备访问的接口。

审查后端必须：

- 在打开浏览器前完成 `/api/health` 健康检查
- 校验 `request_id`、`stage`、`content_hash` 和 `status`
- 使用临时文件加原子替换写入审批结果
- 拒绝旧请求、旧哈希、错误阶段和重复提交
- 对用户输入进行长度、类型和枚举校验
- 不把页面关闭、超时或服务器退出解释为批准
- 不执行来自网页字段的命令、路径或脚本

## 敏感数据处理

不要提交或上传：

- GitHub、云平台或模型服务访问令牌
- SSH 私钥、登录密码和真实集群账户
- 商业软件许可证文件、许可证服务器地址或受限安装包
- 未经授权的未发表结构、轨迹、波函数、检查点和合作数据
- 包含个人身份、单位内网地址或绝对路径的日志

测试和示例应使用最小化、匿名化、可公开的数据。安全修复不得以删除科学来源链、弱化审批校验或自动批准作为临时方案。
