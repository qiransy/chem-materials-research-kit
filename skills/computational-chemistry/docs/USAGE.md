# 使用说明

本文件说明如何以人机协同方式使用 Computational Chemistry Skill。`SKILL.md` 是 AI 执行入口，本文件是面向用户的操作说明。

## 使用前准备

开始前尽量提供以下信息：

- 研究目标和需要回答的科学问题
- 已知实验现象、样品条件和不确定性
- 分子、晶体、表面、界面或结构来源
- 计划使用的软件、版本、模块和许可证条件
- 本地工作站或计算集群的资源限制
- 希望获得的证据，例如能量、结构、电子性质、成键、电荷或动力学信息
- 已经完成的工作、已有文件和当前所在阶段

信息不完整时可以明确写“未知”或“待确认”。Skill 应区分用户事实、合理假设和需要补充的信息。

## 最小启动示例

```text
帮我用 CP2K 优化这个结构。
```

Skill 应逐步询问目标、结构文件、软件版本、运行位置、环境命令、所需文件、回传文件和关键参数。信息完整前不得生成审查页面或正式计算文件；完整后才生成固定的 `.review/review.html`。

## 阶段 1：科学问题与计算方案

适用请求示例：

```text
根据我的研究目标生成阶段 1 计算方案。每个任务必须说明使用的软件和模块、直接计算参数、参数代表的性质、可以支持的结论、不能支持的结论、前置依赖、相互佐证关系、优先级和预计成本。
```

浏览器页面中重点核对：

- 研究对象和比较对象是否正确
- 实验现象是否被准确描述
- 科学问题是否具体且可验证
- 不同任务是否重复回答同一问题
- 每项任务是否真的能提供所声明的证据
- 软件和方法是否符合实际条件
- 是否存在未经用户确认的假设

默认终审操作包括批准、退回修改和拒绝。用户修改后覆盖同一个 `.review/review.html`。显式高级项目仍可使用以下结构化决定值：

- `approved`：批准当前版本并继续
- `revision_required`：退回当前阶段修改，意见必须被保留
- `rejected`：拒绝并终止当前流程

## 阶段 2.1：基础模型、表面和缺陷

适用请求示例：

```text
阶段 1 已批准。请根据已批准任务设计表面和缺陷候选，说明晶面、终止方式、层数、真空层、超胞、固定层、缺陷或掺杂位置、电荷、自旋、结构来源和实验依据，并打开浏览器让我审批。
```

用户需要确认候选模型是否代表真实材料、样品、环境和实验边界。模型未经批准时，不应进入界面、吸附或正式输入文件生成。

## 阶段 2.2：吸附和界面模型

适用请求示例：

```text
请基于已经批准的两个表面构建界面候选，比较晶格匹配、旋转、应变、平移、层间距、接触位点、周期性和固定区域，并打开独立浏览器页面让我审批。
```

该阶段应记录候选构建参数和版本，不得只保存最终结构而丢失生成过程。

## 阶段 2.3：正式输入文件与执行说明

适用请求示例：

```text
界面候选已批准。请按任务依赖顺序生成第一批正式输入文件和执行说明。生成后提醒我不要退出当前会话，等待我完成计算并返回真实结果。
```

默认正式计算目录只包含目标软件必需文件和一个 `README.md`。只有用户明确需要提交脚本时才询问调度资源并生成对应脚本。输入文件生成后，用户负责：

- 核对结构、赝势、基组、力场和参数
- 核对软件版本、模块和许可证
- 在本地或计算集群上实际运行
- 保存实际使用的输入、输出、日志和最终结构
- 记录运行中做过的参数修改

Skill 不应自动连接 SSH，不应替代用户提交 `sbatch`、`qsub`、`bsub`、`srun` 或其他远程任务。

## 返回计算结果

计算结束后建议同时上传：

- 实际运行的输入文件
- 主输出文件
- 标准输出和错误日志
- 最终结构或轨迹
- 调度脚本
- 软件与版本信息
- 用户在运行过程中做过的修改说明

推荐请求：

```text
我已经完成计算。下面上传实际输入、输出、日志和最终结构。请先检查完整性、收敛信息、异常、实际参数和可比性，再告诉我下一步需要处理哪些数据。不要直接生成最终论文结论。
```

静态文件完整、程序正常结束或输出中出现 `converged` 字样，均不自动等于模型合理、所有性质收敛或科学结论成立。

## 阶段 3：数据处理与证据分析

### 用户不知道如何处理数据

```text
我已经得到计算结果，但不知道如何处理。请先概括完整处理流程，用 1、2、3……编号说明每一步。我会告诉你进行到哪一步，或者直接询问不会的步骤。
```

Skill 应先提供整体路线，再按用户指定步骤给出可执行教程。不要一次塞入所有软件命令和全部理论细节。

### 用户已经处理好数据

```text
下面是我整理后的能量、结构、电荷、DOS/PDOS 和成键数据。请依据已批准的科学问题进行针对性分析，区分已证明、部分支持、尚未证明和需要补充的结论，并检查单位、参考态、计算条件和样本是否可比。
```

分析应围绕证据功能，不以自动绘图为默认目标。用户需要作图时，应先确认数据格式、比较口径和图的科学目的。

## 阶段 4：结论与论文计算说明

```text
请根据已经验收的实际输入、输出、日志、最终结构和处理后数据，生成研究结论和论文中的计算方法说明。所有软件、版本、模块、赝势或基组、色散修正、U 值、自旋、k 点、截断能、收敛标准、约束和边界条件必须来自真实记录。
```

如果实际计算使用商业软件，Skill 应如实报告真实软件。可以附加开源软件复现或迁移建议，但不能把开源软件描述成原始结果的真实来源，也不应仅为改写说明要求用户重新计算。

## 阶段 5：归档与交付

```text
请整理最终交付清单，包含已批准方案、模型版本、实际输入输出、处理数据、证据节点、分析结论、论文说明、缺失项、软件替代建议、来源链和建议清理清单。未经我确认不要删除任何文件。
```

建议保留以下追踪关系：

```text
结论
  ↓
证据节点
  ↓
处理后数据
  ↓
用户实际输出与日志
  ↓
用户实际输入
  ↓
模型和参数版本
  ↓
已批准的阶段 1 任务
```

## 浏览器页面没有自动打开

先使用工作流返回的 `.review/review.html` 绝对路径或经过验证的本地地址手动打开。自动打开只是便利功能，失败不会阻断科学分析。

默认静态页面仍然无法访问时，检查路径、文件大小、浏览器对本地文件的限制和页面是否在信息完整后生成。显式高级 Flask 审查无法访问时，再检查：

- `/api/health` 是否成功
- 本地端口是否冲突
- 防火墙是否阻止回环地址
- 是否存在陈旧锁或旧服务器进程
- 当前环境是否为远程容器或 SSH 会话
- 日志中是否有 Flask 启动错误

远程环境需要安全端口转发，不应把审查服务暴露到公网。

## 恢复中断的项目

恢复时上传或提供：

- 当前项目状态文件
- 最近批准的方案版本
- 已生成和已运行的文件清单
- 新增或修改的输入输出
- 最近一次审查决定
- 当前希望继续的阶段和步骤

推荐请求：

```text
请根据我提供的项目状态和新增文件恢复工作流。不要根据聊天记忆猜测缺失历史。先核对当前阶段、已批准任务、模型版本、实际输入输出和待完成事项。
```

## 隐私与安全

不要上传：

- SSH 私钥、令牌和密码
- 商业许可证文件或许可证服务器凭据
- 未脱敏的账户名、主机名和内部网络配置
- 未经授权的未发表数据
- 合作方限制传播的结构或输出

优先使用相对路径、匿名项目编号和最小必要文件。发现敏感信息时，应停止传播并先完成脱敏。
