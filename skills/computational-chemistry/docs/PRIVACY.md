# 隐私与敏感数据指南

Computational Chemistry Skill 可能处理未发表结构、计算输入输出、实验现象、集群脚本和论文草稿。用户应遵循最小必要原则，只提供完成当前任务所需的数据。

## 不应上传或提交的内容

不得上传到对话、GitHub Issue、Pull Request、示例目录、测试夹具或验证报告：

- GitHub Token、API Key、模型服务密钥
- SSH 私钥、公钥对应的真实账户信息、登录密码
- 集群账户、节点内部地址、VPN 配置和跳板机信息
- 商业软件许可证文件、许可证服务器地址和受限安装包
- 未经授权的合作单位材料
- 包含个人身份、联系方式或内部路径的日志
- 受保密协议限制的结构、轨迹、波函数、检查点和数据库
- 可用于恢复真实身份或单位基础设施的信息

## 可安全提供的最小信息

优先提供：

- 匿名项目编号
- 相对路径
- 删除用户名和主机名后的日志片段
- 最小复现输入
- 截断后的错误上下文
- 公开结构或人工构造的测试结构
- 经过脱敏和缩减的处理后数据

不要为了复现界面问题上传完整科研输出。浏览器审查问题通常只需要当前阶段、请求编号、脱敏哈希、HTTP 状态和最小日志。

## 本地浏览器服务

审查服务默认绑定 `127.0.0.1`，页面和 API 仅供本机访问。除非用户明确配置并了解风险，不应绑定 `0.0.0.0` 或公网地址。

远程服务器运行时，建议使用 SSH 或开发工具的本地端口转发，在本地浏览器访问。不要直接开放云主机安全组端口，也不要把审查地址公开分享。

## 运行文件

默认终审文件 `.review/review.html` 以及按需产生的 `.review/review_response.json` 可能包含研究内容或本机信息，不得提交到仓库。正式计算目录中的输入、结构、输出、日志和唯一 `README.md` 也应在分享前脱敏。

显式高级项目还可能包含以下内部文件：

```text
review_request.json
review_decision.json
session.json
lock.json
server.log
project_state.json
```

这些是高级兼容流程的内部记录，不是默认计算交付文件。

归档、提交或分享前应检查并删除：绝对路径、用户名、主机名、账户、内部 IP、许可证信息和未发表正文。

## 日志规则

日志应记录足以诊断问题的事件，但不应默认记录：

- 完整请求正文
- 完整科研方案
- 凭据和请求头
- 用户主目录绝对路径
- 商业许可证环境变量
- 大型输出文件内容

必要时使用请求编号和内容哈希关联事件，而不是重复写入完整内容。

## 示例与测试数据

示例必须使用公开、合成或明确授权的数据。测试夹具不应从真实项目直接复制。截图中应遮挡项目名称、绝对路径、用户名、时间戳中的敏感上下文和未发表内容。

## 第三方服务

本项目本身不要求把科研数据上传到外部服务器。用户所使用的 AI 工具、GitHub、模型服务、浏览器扩展和远程开发平台可能有各自的数据政策，使用前应自行确认。

不要把“本地 Flask 页面”误解为整个工作流完全离线。是否存在外部数据传输取决于用户选择的 AI 平台、模型接口和同步工具。

## 商业软件与知识产权

不得提交商业软件二进制、许可证文件、受限模板、专有数据库或未经许可复制的手册内容。论文方法说明可以如实记录软件名称、版本和方法，但不能将受限资源打包进仓库。

## 删除与清理

Skill 可以提出清理建议，但不得未经用户明确批准自动删除真实输入、输出、日志、结构或归档。清理前应列出拟删除文件、原因、是否可再生成和是否已备份。

## 事件处理

发现凭据或敏感数据已进入仓库时：

1. 立即撤销或轮换相关凭据。
2. 不要仅依赖删除最新提交，因为历史记录中仍可能存在。
3. 按照 GitHub 的敏感数据清理流程重写历史。
4. 检查 Fork、缓存、Release 和自动化产物。
5. 按 `SECURITY.md` 私密报告可能的安全影响。

隐私保护不能通过删除来源链或伪造记录实现。科学数据可以脱敏，但计算来源、软件、版本和证据关系仍应如实保留。
