# Browser review

## When review starts

The default browser review begins only after stage-1 intake is complete and internally consistent. A short request does not create a page. The workflow first confirms the calculation goal, structure or existing files, software/version, run location, environment-loading command, requested deliverables, required returned files, key parameters, and—only when a scheduler script is requested—the scheduler resources.

Before that gate passes, the workflow must not create `.review/`, calculation inputs, review records, manifests, or status files.

## Fixed artifacts

The final review page has one fixed path:

```text
.review/review.html
```

Generate it after intake completion. If the user revises the request, overwrite this file. Do not create `review_v1.html`, `review_v2.html`, `review_final.html`, timestamped copies, or a review history directory.

Only an automated return channel that genuinely needs a file may also use:

```text
.review/review_response.json
```

A static page may let the user download this response. It must not pre-create an empty response file.

The deterministic default implementation is `scripts/staged_review.py`:

```text
python scripts/staged_review.py check intake.json
python scripts/staged_review.py render intake.json <project-directory>
```

`check` reports missing fields without generating files. `render` refuses incomplete intake and otherwise creates or overwrites the fixed HTML page.

## Page design

Present the request as understandable sections and controls: text fields, text areas, drop-down lists, switches/checkboxes, and numeric inputs. Show the goal, structure, software/version, environment, deliverables, returned-result requirements, key parameters, warnings, and the user decision. Do not require a nontechnical user to edit a large JSON document.

Do not display secrets, license keys, credentials, private server addresses, or arbitrary shell controls.

## Opening the page

Automatic browser opening is optional convenience, not a workflow gate. On Windows, any PowerShell attempt must use PowerShell 7 with:

```text
pwsh -NoLogo -NoProfile -NonInteractive
```

Use a finite timeout and captured standard output/error. An exit code of zero only means that the open request was accepted; it does not prove that the page was viewed or approved.

If the browser cannot be opened, provide the absolute path to `.review/review.html` or a verified local URL. Review and scientific analysis continue; no extra status or failure record is generated by default.

## Approval and calculation files

After the user approves the current page, generate only the target program's necessary input/structure/parameter files and one `README.md`. The README contains run commands, parameter notes, expected outputs, and return-file instructions. Keep `.review/` out of the formal calculation directory and out of Git.

## Advanced compatibility

Existing version 1.0 advanced projects may use the implemented Flask server, hash-bound `review_request.json`/`review_decision.json`, immutable versions, and project-control records. This is an explicit compatibility route, not the default for a new simple request. Preserve its records and do not claim its checks ran unless the corresponding scripts actually executed.
